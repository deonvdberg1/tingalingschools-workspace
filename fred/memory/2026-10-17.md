## 12:05 SAST — ⚠️ FOUND: 2 missed nightly backups (Oct 16 + Oct 17) → fixed

**Symptom:** `backups/` jumped from `2026-10-15_02-00` to `2026-10-17_11-39` — the 02:00 cron backup silently did not run on **Oct 16** or **Oct 17** (and there is no 2026-10-16 snapshot at all).

**Cause:** the backup was a **cron** job (`0 2 * * *`). The Mac sleeps overnight (power settings: `sleep 1`, displaysleep 20, no active caffeinate until 11:35 today). macOS **cron does not run jobs missed during sleep**, while the `*/5` and `*/10` jobs simply resume on wake — which is why watchman/site-monitor looked healthy and only the 02:00 job vanished. Manual run works fine (exit 0).

**No data lost:** git pushes are continuous and a full snapshot exists from today (11:39 + 12:03). But the nightly safety net was silently broken.

**Fix (implemented + verified):**
1. **Idempotency guard** in `scripts/backup.sh` — at most one snapshot per day (`compgen -G backups/YYYY-MM-DD_*` → skip). Prevents double runs when cron + launchd both fire.
2. **New LaunchAgent `com.autoeffortless.backup`** (`~/Library/LaunchAgents/com.autoeffortless.backup.plist`) — `StartCalendarInterval` 02:00 daily, `RunAtLoad false`, output to `fred/logs/backup.log`. **launchd re-runs missed calendar jobs on wake**, unlike cron. Loaded and confirmed (`launchctl list` → `- 0 com.autoeffortless.backup`).
3. Guard verified: a manual run now correctly prints "Snapshot for 2026-10-17 already exists — skipping" and exits 0.

**Also noted:** `scripts/healthcheck.sh` has **no backup-freshness check** — nothing would have alerted anyone. (The old heartbeat line "backup present" was a manual check, not automated.) Candidate: add a freshness check (>26h = alert) to the provider-independent `api-watchdog.sh`, which alerts by email/WhatsApp/macOS notification.
