**Lessons learned this round (worth remembering):**
1. **AuthContext session restore requires BOTH `ae_token` AND `ae_user` in localStorage.** The scan page initially set only `ae_token` → after redirect to `/`, AuthProvider skipped restore (needs both keys) → user null → ProtectedRoute bounced to /signin. Fix: after scan, fetch `/api/auth/me` with the new token, store `ae_user` too, then redirect. (Any future "magic login" flow must mirror this.)
2. **Puppeteer `waitForFunction` runs the predicate IN-PAGE** — Node-side variables like `page`/`fresh` are not accessible; use `location.href`/`document` inside. Caused a false "redirect never happened" timeout.
3. **The `write` tool intermittently sanitizes `'Bearer ' + token` into literal `***` in helper scripts** (happened twice today). If a script 401s for no reason, grep the file for `***` and sed-fix. Use `'Bearer ' + token` written via sed/python when suspicious.
4. **sql.js DB**: test staff/user rows accumulate across failed E2E runs — clean by name prefix, not id (ids collide across runs). Leftover test users (sipho/bulkone/lerato.stafftest@example.com, role staff, no links) remain in users table — harmless, purge later if desired.
5. **pdfkit** was installed in dashboard-api (for the poster PDF) — now unused after poster removal. Harmless dep; can remove later.
